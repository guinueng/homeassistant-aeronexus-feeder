# 검증 결과와 실제 장비 확인 범위

검증일: 2026-10-31 (한국 시간).

## 수행한 검사

| 항목 | 결과와 범위 |
|---|---|
| 업로드 원본 확인 | 실제 첨부파일 44,771바이트를 읽고 SHA-256 기록 |
| 원본 중계기 추출 | 원본 PYEOF Python 344줄을 비교용으로 보관 |
| 프로토콜 회귀 검사 | `tests/test_relay.py`의 **25개 검사 통과** |
| 모의 TCP 통합 검사 | 127.0.0.1의 임시 포트에서 실제 socket으로 전달·심장박동·재접속 확인 |
| UUID | 38바이트 식별 프레임, 서버 재연결 시 재전송, 재시작 때 새 UUID 사용 |
| Beast 필터 | DF17/18 선택, `all`에서도 MLAT 제외, timestamp/payload의 1A escape |
| 잘린 스트림 | 모든 분할 경계, 무작위 chunk, 외부 UUID/E3 ID 제외, 잘못된 프레임 복구 |
| 재연결 | 소스/서버 각각 끊고 재접속, 소스 세션 간 불완전 프레임을 이어 붙이지 않음 |
| 옵션 | 빈 UUID 대기, 잘못된 UUID/형식/포트/알 수 없는 키 거부, 기본값 |
| 자동 탐색 | 표준/로컬 slug 변환, 중복/없음 오류, 직접 주소 시 API 생략, 캐시 갱신 |
| API 권한 | GET info 경로와 Bearer 헤더 모의 검사; redirect 시 토큰 전달 거부 |
| 네트워크 정지 방지 | 연결된 소켓에 5초 타임아웃 설정 확인. 실제 장기 혼잡 부하 시험은 아님 |
| YAML | PyYAML로 config/한국어/영어 3개 파일 파싱, 기본값·선택 옵션·번역 키 일치 검사 |
| 파일/서비스 구조 | Python 구문, S6 longrun/base 의존성/user bundle, UTF-8/LF/BOM, 문서 링크 검사 |
| 셸 구문 | `run`, `finish`를 Bash `-n`으로 검사 통과 |
| 최신 문서/UI | SOURCES.md의 공식 문서 및 실제 Frontend/Supervisor 소스와 대조 |
| ZIP | 파일 CRC, 원본 소스와 내용 일치, 경로 이탈 없음, 단일 최상위 소스 폴더 검사 |

테스트 환경은 Windows의 Python 3.14입니다. 모의 TCP 검사는 이 컴퓨터 내부에서만 실행했고
실제 AeroNexus 서버에 테스트 UUID나 가짜 ADS-B 자료를 보내지 않았습니다.
Home Assistant 내부 DNS/권한은 공식 구현과 대조하고 API 응답을 모의해 검사했습니다.

YAML 일관성 검사는 **실행 중인 Supervisor의 전체 설정 검증기를 호출한 것은 아닙니다.**
옵션 스키마와 설정 키는 공식 문서/코드에 맞춰 확인했으며 실제 Supervisor의 최종 판정은
사용자 HAOS 설치 과정에서 이뤄집니다.

## 아직 실측하지 않은 항목

- 이 작업 환경에서는 Docker Linux 엔진이 실행 중이 아니어서 이미지를 빌드하지 않았습니다.
- 사용자 HAOS 장비에 설치하거나 실제 Frontend 화면을 열어 조작하지 않았습니다.
- `aarch64`/`amd64` 실제 이미지 빌드·부팅은 미수행입니다. 베이스 이미지의 공식 지원 구조를 사용했습니다.
- 사용자의 기존 피더 버전, 실제 내부 DNS/바인딩, UUID 등록 상태는 조회하지 않았습니다.
- 실제 AeroNexus 서버의 UUID 승인·저장·지도 노출은 확인하지 않았습니다.
- 실제 Home Assistant 백업 복원/재부팅 시험은 수행하지 않았습니다.

따라서 결과물은 **설치용 전체 소스**이며, 사용자 장비에서 설치 완료 또는 실서버 피딩 성공을
이미 확인했다는 뜻은 아닙니다. 가이드에 조건과 확인 방법을 명시했습니다.

## 사용자 장비에서 마무리할 확인

| 순서 | 수행 | 성공 기준 |
|---|---|---|
| 1 | 소스 복사 → 스토어 업데이트 확인 | Local apps에 AeroNexus Feeder가 나타남 |
| 2 | 설치 | 실제 장비에서 이미지 빌드가 완료됨 |
| 3 | UUID 빈 상태에서 시작 | 대기 로그만 출력, 서버 연결 없음 |
| 4 | 발급 UUID 저장 → 재시작 | Beast 연결 및 UUID frame sent 로그 |
| 5 | 1~2분 수신 | 실제 항공기 수신 중이면 input/eligible/sent 증가 |
| 6 | AeroNexus에서 수신 확인 | 해당 UUID의 자료가 서버에 들어옴; 지도 공개는 별도 확인 |
| 7 | 기존 피더 잠시 중지 후 시작 | 이 앱이 수신기 끊김을 감지하고 자동 재연결 |
| 8 | HAOS 재부팅 | Start on boot가 켜진 두 앱이 순서와 무관하게 재연결 |
| 9 | 앱 포함 백업 생성/보관 | 앱 옵션과 소스 ZIP을 장비 밖에 보관 |

개발 환경에서 다시 실행하려면 앱 소스 폴더에서 다음을 사용하세요.

```sh
python3 -B -m unittest discover -s tests -v
```

로컬 네트워크 연결을 허용한 Python 3.10 이상 환경이 필요하며, 앱 실행 이미지에는
테스트 도구나 PyYAML/voluptuous를 설치하지 않습니다. 실행 중계기는 Python 표준 라이브러리만 사용합니다.
