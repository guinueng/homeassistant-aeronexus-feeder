# 1.1.4 검증 결과

- Windows와 Ubuntu(WSL)의 Linux Python에서 각각 80개 회귀 검사 통과.
- 서버의 즉시 EOF/reset/broken pipe 시 특수 종료 코드 78로 중계기 종료. 모의 서버에서 추가 연결 없음 확인.
- 관리자 재실행·후보 검사 실패의 이전 코드 재접속·주소 재탐색 중 종료 상태 유실 차단 검사.
- Supervisor 자기 앱 중지 한 번 요청, API 오류·토큰 없음·redirect·응답 오류에도 재접속 없이 대기 검사.
- 수동 새 앱 실행에서 연결 재시도 가능, 일반 작업 프로세스 실패 시 기존 재시작 유지 검사.
- Beast 수신기 종료/연결 거절/시간 초과/로컬 종료/장시간 연결 종료의 오탐 방지 검사.
- 실제 공식 중계기 프로세스의 종료·WARNING·UUID 비노출, 진단 로그/소켓 정리 실패에도 종료 확인.
- 원본 Python 파일과 초기 중계기의 SHA-256 유지, UUID/Beast/DF17/18/MLAT 프로토콜 검사.
- 최초/새 앱 버전/수동 갱신 정책, 캐시·복구·옵션 보존·비밀값 비노출 회귀 검사 유지.
- 공식 서버에 시험용 ADS-B 자료나 UUID를 전송하지 않음.
- 일반 사용자 Linux 하위 프로세스 실행 확인. 1.1.4 Docker 이미지 빌드는 로컬 Docker 엔진 시작 실패로 미완료.
- 이전 1.1.3의 amd64/aarch64 이미지 빌드는 통과했으며, 1.1.4의 Dockerfile 변경은 BUILD_VERSION 값입니다.
- YAML, 번역, 파일 해시, UTF-8/LF, 문서 링크 및 ZIP 내용 검사.

사용자 HAOS에서의 실제 자기 앱 중지·Watchdog·재부팅·백업 복원과 실제 UUID의 수신은 미실측입니다.
자기 앱 중지는 모의 API와 Supervisor 공식 구현으로 검증했습니다. API 실패 시 관리 프로세스는 대기하고 중계는 종료됩니다.
tests/RESULTS.txt에 최종 검사 결과를 포함합니다.
