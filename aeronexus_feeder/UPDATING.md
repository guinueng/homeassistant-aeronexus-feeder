# 최신 코드 확인과 복구 — 1.1.1

## 언제 확인하나?

- UUID를 설정한 최초 실행 때 한 번 확인합니다.
- 새로운 HA 앱 버전으로 업데이트하면 그 버전의 첫 실행 때 한 번 확인합니다.
- 같은 앱 버전으로 재시작하거나 실행 중일 때는 다시 확인하지 않습니다.
- 최초 확인에 실패하면 현재 코드로 실행하고, 다음 앱 재시작 때 한 번 재시도합니다.

1.1.0의 매시간 확인은 제거했습니다. 저장되어 있는 update_interval 옵션도 무시합니다.
성공한 확인은 /data/upstream/state.json의 checked_app_version에 기록합니다.
이 상태는 앱 백업에 포함되고 재부팅 후에도 유지됩니다.

## 다운로드/검사/적용

공식 HTTPS feed.sh에서 Python 중계기 전체를 추출합니다. 문법, UUID 프레임, DF17/18,
MLAT 제외, Beast 분할/escape 및 실제 main 전송 루프를 별도 일반 사용자 프로세스로 검사합니다.
통과하면 실행하고, 초기 30초간 종료되지 않으면 정상 버전으로 저장합니다.
원본에 릴리스 번호가 없어 코드 SHA-256을 버전으로 기록합니다.

목적지는 원본의 리터럴 기본값을, UUID/Beast 주소/필터는 HA 설정을 사용합니다.
원본 shell/systemd 설치기는 실행하지 않습니다. Supervisor 토큰을 하위 프로세스에 넘기지 않고
UUID 로그를 숨깁니다. 통계 간격과 5초 송신 타임아웃을 적용합니다.

## 복구

- 다운로드/HTTPS/문법/호환성 실패: 기존 버전 유지. 실행 중 자동 재확인은 하지 않습니다.
- 새 프로세스가 초기 30초 안에 종료: 이전 버전으로 복구합니다.
- 적용 중 앱이 종료: 다음 시작 때 이미 받은 후보를 캐시에서 다시 검사하며 HTTP 요청은 하지 않습니다.
- 캐시 손상: 유효한 이전 캐시 또는 이미지의 초기 코드로 복구합니다.
- 새 원본의 구조/프로토콜이 호환되지 않음: 기존 코드를 유지하고 어댑터 업데이트를 기다립니다.

30초 확인은 프로세스 유지 검사이며 서버의 UUID 승인/자료 저장 보장은 아닙니다.
코드 교체 때 잠깐 재연결하며 오프라인 자료를 저장해 나중에 재전송하지 않습니다.

## 이후 업데이트

실행 중 코드를 바꾸려면 새로운 HA 앱 버전을 설치합니다. 설정 UI/업데이터/Dockerfile도 같은 경로로
업데이트합니다. HA의 앱 자동 업데이트를 켤지 여부는 사용자 설정입니다.
1.0의 소스 내장형 설치 파일은 고정본이므로 새 저장소 앱으로 이동해야 합니다.
