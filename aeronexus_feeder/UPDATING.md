# 자동 업데이트와 복구

## 확인/적용

1. UUID가 설정된 앱은 시작 시 공식 HTTPS feed.sh를 확인합니다.
2. 실행 중 `update_interval`마다 확인합니다. 기본 3600초, 범위 300~86400초입니다.
3. ETag/Last-Modified가 있고 유효한 캐시가 있으면 조건부 요청을 사용합니다.
4. 변경된 원본은 최대 2 MiB, 추출된 PYEOF Python 코드는 최대 512 KiB로 제한합니다.
5. Python 문법 및 uuid_frame/Splitter/main 인터페이스를 확인합니다.
6. 별도 일반 사용자 프로세스에서 UUID 프레임, DF17/18, MLAT 제외, 분할/escape를 검사합니다.
7. 통과하면 이전 프로세스를 중지하고 새 Python 중계기 전체를 실행합니다.
8. 30초간 프로세스가 유지되면 활성 버전으로 저장합니다.

원본에 일정한 릴리스 번호가 없어 SHA-256을 코드 버전으로 사용합니다.
목적지 주소/포트의 리터럴 기본값도 원본에서 추출합니다.
코드와 목적지가 같으면 실행 중인 프로세스를 바꾸지 않습니다.

원본 shell은 실행하지 않습니다. 이미지의 aeronexus 일반 사용자로 Python을 실행하고,
Supervisor 토큰과 부모의 다른 인증 환경 변수는 전달하지 않습니다.
HA 실행기는 통계 간격과 5초 송신 타임아웃을 적용하며 UUID 로그를 숨깁니다.

## 실패 처리

- 다운로드/HTTPS/문법/호환성 실패: 기존 버전을 유지하고 다음 주기에 재시도.
- 초기 30초 내 종료: 이전 활성 버전으로 복구하고 같은 실패 버전은 다시 적용하지 않음.
- 캐시 손상: SHA-256 검사 후 이전 캐시, 그마저 없으면 내장 초기 코드 사용.
- 새 원본이 기존 검사와 호환되지 않음: 로그를 남기고 기존 버전 유지. HA 어댑터 업데이트가 필요할 수 있음.

30초 확인은 프로세스 유지 검사이며 서버 승인/자료 저장 확인은 아닙니다.
적용 도중 HA가 종료되면 활성화되지 않은 새 코드는 다음 시작 때 다시 검증합니다.
교체/재연결 중 오프라인 자료를 디스크에 저장해 재전송하지 않습니다.

## HA 앱 자체 업데이트

설정 UI/업데이트 관리자/Dockerfile은 GitHub의 앱 버전을 올려 배포하고 HA의 앱 업데이트로 적용합니다.
원하면 HA에서 해당 앱의 자동 업데이트 설정을 사용하세요.
1.0의 소스 내장형 설치 파일은 고정본입니다. 지속 업데이트에는 1.1.0 이상 설치가 필요합니다.
